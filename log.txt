1. RESUME (15 lignes max)
================================================================================
Le projet est une application web full-stack (pas mobile natif) servant de
prototype fonctionnel pour SafeTrack. Il comprend deux variantes : une maquette
statique monofichier (safetrack-app.html, 899 lignes, donnees en dur) et une
version "connectee" (frontend/ + backend/) censee consommer une vraie API REST.

PROBLEME BLOQUANT (CRITIQUE) : le backend ne demarre pas. Il exige Node >= 22.5
pour le module natif node:sqlite, mais Node v20.19.0 est installe. Resultat :
l'application complete est inutilisable en l'etat sur cette machine.

Cote fonctionnel, les besoins B1 (alerte 1 geste) et B4 (CRUD contacts) sont
partiellement cables via l'API. En revanche B2 (GPS reel), B3 (audio), B5
(carte SDK), B7 (acces autorites) et B8 (chiffrement, auth reelle) sont absents
ou purement simules/affiches. Le profil affiche "deuxFacteursActif" en clair
(texte de developpeur visible dans l'UI). Aucun systeme git, aucun test, aucune
CI, 4 vulnerabilites npm (1 critique, 3 moderees). Interface en theme sombre
par defaut (violation regle design : theme clair requis au premier lancement).

--- ENV-01 / BLD-01 (CRITIQUE) ---
Constat : Node.js v20.19.0 installe sur la machine. Le module node:sqlite est
          disponible uniquement a partir de Node 22.5.0. Le projet le declare
          explicitement (package.json:11 : "node": ">=22.5.0").
Preuve   : commande `node server.js` -> ERR_UNKNOWN_BUILTIN_MODULE: node:sqlite
           (db.js:6 : const { DatabaseSync } = require('node:sqlite'))
Impact   : Le backend ne demarre pas. Toute l'API est inaccessible. L'application
           complete est non fonctionnelle sur cette machine.

--- ENV-02 (MAJEUR) ---
Constat : Aucun repertoire .git a la racine du projet.
Preuve   : `git log` -> "fatal: not a git repository"
Impact   : Aucun historique de version, aucune tracabilite des modifications.

--- ENV-05 (MINEUR) ---
Constat : .gitignore ligne 3 : "*.log" - si git est initialise, log.txt
          sera ignore par defaut.
Preuve   : .gitignore:3
Impact   : Le fichier log.txt cree par cet audit ne serait pas versionne.

--- ENV-06 (MAJEUR) ---
Constat : safetrack-app.html (188 Ko, 899 lignes) a la racine est une maquette
          statique anterieure avec donnees mockees en dur (pas d'appel API).
          Il coexiste avec le frontend/ connecte sans documentation claire
          sur lequel est la version de reference.
Preuve   : safetrack-app.html:1-50 - CSS inline, pas d'appel fetch
Impact   : Confusion sur l'etat reel du projet. Risque de travailler sur la
           mauvaise version.

--- BLD-02/03 (CRITIQUE/MAJEUR) ---
Constat : npm audit signale 4 vulnerabilites dans les dependances d'Express 4.19.2.
          - proxy-addr <= 2.0.7 : CRITIQUE - IP spoofing (GHSA-jqcg-44mw-7w3h)
          - qs <= 6.15.3 : MODERE - array-limit bypass, DoS (2 CVE)
          - body-parser 1.20.5-1.20.6 : MODERE - depend de qs vulnerable
Preuve   : `npm audit` (sortie complete ci-dessus)
Impact   : Risque d'usurpation d'IP source. Risque de DoS par payloads malformes.

--- B1 (PARTIEL/MAJEUR) ---
Constat : Le bouton SOS (index.html:133) declenche en 1 clic un appel POST
          /api/alerts (app.js:80-86) - c'est reel. Mais aucun "mode urgence"
          persistant : l'etat de l'app n'est pas modifie (pas de variable
          globale d'etat, pas d'UI differente, pas d'ecran de suivi dedie).
          Le toast (3,2 s) est la seule consequence visible.
Preuve   : app.js:80-86 - pas de changement d'etat apres createAlert()
Impact   : L'utilisateur ne sait pas visuellement si l'alerte est toujours
           active. Pas de passage en "mode urgence" selon B1.

--- B2 (MAQUETTE/CRITIQUE) ---
Constat : Aucun appel a navigator.geolocation dans tout le code frontend.
          La fonction updateRadarReadout() (render.js:112-119) simule des
          coordonnees par jitter aleatoire (Math.random()) a partir des donnees
          SQLite du premier tracker. Aucun envoi aux contacts (SMS, push, email,
          WebSocket non implemente).
Preuve   : render.js:114-116 - jitterLat = tracker.lat + (Math.random()-0.5)*0.0006
           grep navigator.geolocation -> aucun resultat
Impact   : La localisation est entierement fictive. Les contacts ne recoivent
           rien en temps reel (B2 non conforme au cahier des charges).

--- B3 (ABSENT/CRITIQUE) ---
Constat : Aucun appel a MediaRecorder, getUserMedia ou equivalent dans tout
          le code frontend. Aucune route backend pour recevoir/stocker de l'audio.
Preuve   : grep MediaRecorder, getUserMedia -> aucun resultat
Impact   : L'enregistrement audio automatique (B3) est entierement absent.

--- B4 (PARTIEL/MAJEUR) ---
Constat : CRUD contacts fonctionnel en DB (contacts.js CRUD complet). Mais :

Preuve   : app.js:90, db.js:34-41 (schema contacts_confiance sans colonne
           "permissions")
Impact   : Impossible de configurer finement les droits par contact (B4 partiel).

--- B5 (MAQUETTE/CRITIQUE) ---
